ONGOING PROCESSOR BUILD

32-bit digital systems

Structural Verilog components built toward a complete processor in Duke’s Digital Systems course.

VerilogIcarus VerilogGTKWave
  • ALU with two-level carry-lookahead arithmetic, bitwise logic, and five-stage barrel shifters.
  • Dual-read register file with one write port and a hardwired zero register.
  • Early shift-and-add multiplier checkpoint with accumulation and result-ready control.
Design choices and verification

The ALU shares an adder between addition and two’s-complement subtraction. Four 8-bit carry-lookahead blocks form the arithmetic unit; separate stages implement logical-left and arithmetic-right shifts.

The register-file archive includes a saved 34,096-case simulation log reporting zero errors. Its expected and actual outputs match under the supplied testbench’s comparison rules. This is simulation evidence, rather than an FPGA timing or board result.

The archived multiplier is an early checkpoint: division is not yet implemented in that version, and signed exception handling remains unfinished.

SIMULATION PROJECT

Robot-arm manipulation

Motion planning, Cartesian placement, and block stacking with a simulated Kinova Gen3 Lite arm.

PythonROS 2MoveItGazebo / RViz
  • Extended course scaffolds with placement and multi-block stacking routines.
  • Changed collision scenes to compare blocked, unobstructed, and detour motions.
  • Added gripper-position checks and a retreat-and-stop policy for a rejected grasp.
My implementation and recorded results

Placement computes release height from the stack layer, descends using Cartesian motion, releases and detaches the block, then retreats. A loop places two blocks onto a third to build a tower.

The detour experiment samples an interior point of a baseline trajectory and uses forward kinematics to position a collision box. Saved logs show both baseline and detour motions succeeding; the two trails are recorded in different colors.

I extended provided arm and simulation helpers rather than implementing MoveIt itself. The grasp check is implemented in code; repeated recovery-performance measurements are a next step.
